# CdRotationProbe

Измеряет геометрию спирали CD самим приводом, по времени чтения секторов, и строит по ней пресет. `make_template.py` собирает в папку `template/` шаблоны для подгонки картинок под кольцо диска.

Инструмент работает на Linux и требует Python 3, numpy и Pillow. Pillow нужен только для `photo_offset.py` и `make_template.py`. Запись на диск скрипты не выполняют: они посылают приводу только READ CD, SET CD SPEED и TEST UNIT READY.

## Быстрый старт: напечатать картинку на диск с готовым пресетом

Замеры здесь не нужны. Раздел подходит для CD-RW комплекта с пресетом `noname-cd-rw-infodisc`: Infodisc, ATIP `97:25/31`, 359848 секторов. На других дисках снова могут появиться кольца, сначала проверьте их через `check_disc.py`.

Команды запускаются из корня репозитория. Нужны .NET 10 SDK и `cdrecord`.

**1. Подготовить картинку.** Холст 2400×2400 px, важное в кольце 520–1200 px от центра. Шаблоны не хранятся в git, один раз соберите их командой `python3 tools/CdRotationProbe/make_template.py`. Проще всего положить сверху `tools/CdRotationProbe/template/disc-overlay-2400.png`, подогнать фото и экспортировать PNG без шаблона. Подробнее в разделе [Шаблоны для картинок](#шаблоны-для-картинок).

**2. Собрать трек.** `--tone-dither 1` нужен для полутонов, для чисто чёрно-белой картинки уберите его.
```bash
dotnet run --project src/DiscImageStudio.Cli -c Release -- \
  cd-generate --input картинка.png --output track.wav \
  --preset noname-cd-rw-infodisc --tone-dither 1
```

**3. Посмотреть результат без записи.** Отверстие и края здесь просто белые.
```bash
dotnet run --project src/DiscImageStudio.Cli -c Release -- \
  cd-preview-track --track track.wav --output preview.png \
  --preset noname-cd-rw-infodisc --size 1000
```

**4. Вставить диск и проверить его.** Новому диску может понадобиться около минуты, чтобы привод его распознал.
```bash
cdrecord dev=/dev/sr0 -minfo | grep 'disk status'
```

| Ответ | Что значит |
|---|---|
| `empty` | Диск пустой, переходите к шагу 6 |
| `complete` | Диск записан, сначала сотрите его |
| `No disk` | Подождите минуту и повторите. Если не помогло, проверьте, что диск лежит блестящей стороной вниз и защёлкнут на шпинделе |

**5. Стереть, если диск записан.** Запись будет уничтожена.
```bash
cdrecord dev=/dev/sr0 blank=fast
```

**6. Записать.** Около 6 минут, диск не вынимать. Нужен именно `-dao`: трек занимает диск до самого конца.
```bash
cdrecord dev=/dev/sr0 speed=16 -dao -audio track.wav
```

Смотреть под одной яркой лампой, медленно наклоняя диск.

## Зачем это нужно

Картинка на диске получается, только если генератор знает угол каждого сектора. На диске около 22 000 оборотов, поэтому даже 0,01 мм ошибки в радиусе дают примерно 20 оборотов ошибки по углу. Изображение распадается на кольца: линии вдоль оборота остаются, всё радиальное исчезает.

Паспортных значений для этого не хватает. Пример с измеренного диска:

| Геометрия | Ошибка фазы на этом диске |
|---|---|
| Стандартный `cd-80` | 383 оборота |
| Пресеты других дисков | 36–45 оборотов |
| Лучший постоянный шаг | до 255° |
| Кубический шаг | до 4° |
| Кубический шаг и таблица поправки | около 0,3° (rms) |

## Принцип измерения

В режиме CAV диск вращается с постоянным периодом `T`, поэтому время завершения чтения сектора привязано к его углу:

```
(t_B - t_A) mod T = (θ_B - θ_A) / ω
```

Чтобы ответ не пришёл из кэша, секторы читаются парами на расстоянии не менее 3000 секторов: каждое чтение требует перехода, а кэш привода хранит только последний участок.

Шум одного чтения около 0,5°. При двух разных скоростях привод давал одну и ту же фазу, значит, это геометрия диска, а не особенность его тайминга. После стирания и новой записи геометрия не меняется: это свойство канавки, поэтому измерять можно по любой полной записи.

Что определяется:
- **`T`:** свёртка времён чтения со случайными паузами, поэтому кратные периоды отсекаются.
- **Целые обороты:** их не видно в одной паре. «Лестница» смещений (1…2048 секторов) даёт локальный наклон, он предсказывает каждое звено цепочки с шагом 3000 секторов, и остаток округляется до целого.
- **Биения канавки:** плотный замер с шагом 500 секторов. Это отклонения до ±3–4° с масштабом в миллиметры, общие для всех направлений. Гладкий шаг их описать не может, для них есть `phaseCorrectionDegrees`.

## Что тайминг измерить не может

Чтение завершается после конца сектора, поэтому фаза смещена относительно положения байтов на постоянное число секторов. Каждый сектор такого смещения даёт около 21° разницы между внутренним и внешним краем. Это одно число приходится брать с фото прожжённого креста.

Абсолютный масштаб радиусов тоже рассчитан при скорости 1200 мм/с и не проверяется: другая скорость немного изменит размер картинки, но не углы.

## Порядок работы

Нужен диск, записанный целиком. Подойдёт запись любого трека на все секторы.

Узнать число секторов:
```bash
cdrecord dev=/dev/sr0 -toc | tail -1
```

**1. Замеры.** Около 15 и 17 минут.
```bash
python3 survey.py coarse coarse.jsonl --sectors 359848
python3 survey.py dense dense.jsonl --sectors 359848
```

**2. Решение.** Получается профиль фазы.
```bash
python3 solve.py coarse.jsonl dense.jsonl phase.npz --sectors 359848
```
В выводе смотрите:
- `largest deviation from prediction`: должно быть намного меньше 0,25 оборота. При превышении скрипт останавливается.
- `Withheld long pairs`: контрольные пары, в решении не участвуют. У измеренного диска это 3,2° rms.

**3. Прожечь крест** с предварительной геометрией, смещение пока 1 сектор. Удобно собрать пресет так:
```bash
python3 make_preset.py phase.npz --sectors 359848 --offset 1 --id draft --name draft --output draft.json
```
Значения из него передаются в `cd-generate` опциями `--r0`, `--r1`, `--sectors`, `--pitch-linear`, `--pitch-quadratic`, `--pitch-cubic`. Картинка для креста: `src/DiscImageStudio.Core/Calibration/Patterns/target_slim.png`. Рядом с треком появится `<трек>.json`, он нужен на шаге 5.

Если крест прожигается с другим пресетом, это тоже нормально: шаг 5 учитывает геометрию из `<трек>.json`.

**4. Снять крест и развернуть фото.** Нужны 3–4 кадра с одной лампой, в кадре весь край диска. Поворачивайте диск между кадрами, чтобы яркая полоса попадала на разные лучи.
```bash
python3 photo_offset.py photo1.png photo2.png photo3.png --polar-dir polar
```
В `polar/` появятся развёртки: столбец соответствует 0,25°, строка 0,1 мм. Кольца там горизонтальные, лучи вертикальные. Запишите номера столбцов чётких лучей.

**5. Найти смещение.**
```bash
python3 photo_offset.py --phase phase.npz --sidecar cross.wav.json \
  --arm photo1.png:490,1210 --arm photo2.png:315,1030
```
Лучи, которые плохо согласуются с остальными (менее 0,5), отбрасываются автоматически. Значимо только `Sector offset`. На измеренном диске это 0,947 ± 0,012.

**6. Собрать пресет.**
```bash
python3 make_preset.py phase.npz --sectors 359848 --offset 0.947 \
  --id my-disc --name "Мой диск" --output my-disc.json
```
Объект из файла добавляется в `cdPresets` файла `src/DiscImageStudio.Core/Presets/built-in-disc-presets.json`. Поля `displayNameResourceKey` и `descriptionResourceKey` добавьте вручную: их требует тест встроенных пресетов. Также обновите ожидаемое число пресетов в `tests/DiscImageStudio.ArchitectureTests/Program.cs`.

**7. Проверить результат.** Прожечь крест уже с пресетом: лучи должны стать прямыми, а их форма не должна совпадать между лучами.

### Подходит ли готовый пресет к другому диску

Нужен записанный диск. Около двух минут, только чтение:
```bash
python3 check_disc.py --preset noname-cd-rw-infodisc
```

| Результат (rms) | Что значит |
|---|---|
| меньше 5° | Диск подходит |
| 5–30° | Похожая, но другая геометрия: будут изгибы |
| больше 30° | Другая геометрия: будут кольца |

Совпадение ATIP не гарантирует совпадение геометрии, для этого и нужна проверка.

## Точность

Данные диска `noname-cd-rw-infodisc`, привод Optiarc AD-5240S (SATA), запрошенная скорость 16x CAV, `T` = 27,683 мс.

| Проверка | Результат |
|---|---|
| Обороты на всём диске | 22158,88, без потери цикла |
| Контрольные пары к кубической модели | 3,2° rms, максимум 6,3° |
| Лучи на фото, до поправки | около 1,6° rms |
| Лучи на чистых снимках, после поправки | 0,15–0,23° |
| Второй и третий диск комплекта против профиля первого | 0,6° rms, максимум 1,5° |

Ограничения:
- **Низкие частоты:** из-за ухода на дальних прыжках (около 2° на проход по диску) известны примерно до ±1°. Это почти незаметно глазу.
- **Мелкая рябь:** на линиях остаётся рябь 0,2–0,4 мм с периодом порядка 1,2 мм. Причина не установлена: она плохо повторяется между снимками, тайминг её почти не видит.
- **Край диска:** на последних 1,5 мм (примерно от r = 56,5 мм) при чтении бывают ошибки. Причина не доказана, предположительно это слабый сигнал CD-RW.
- **Другие приводы:** метод проверен на одном приводе. На других могут быть другие кэш и режимы CAV. Проверка: период из `solve.py` должен быть одинаковым на всех радиусах.

## Шаблоны для картинок

Холст 2400×2400 px, центр холста совпадает с центром диска. Половина ширины холста соответствует 57,5 мм, то есть 1 мм = 20,87 px.

| Зона | Радиус, px | Радиус, мм | Что с ней |
|---|---|---|---|
| Отверстие | 0–520 | 0–24,9 | Не печатается |
| Надёжная зона | 553–1169 | 26,5–56 | Для лиц и текста |
| Кольцо целиком | 520–1200 | 24,9–57,5 | Печатается |
| Углы холста | больше 1200 | больше 57,5 | За краем диска |

Значение 520 px верно для `noname-cd-rw-infodisc`. Для другого диска пересоберите шаблоны: `python3 make_template.py --inner-mm 24.9`.

| Файл в `template/` | Что это | Как использовать |
|---|---|---|
| `disc-overlay-2400.png` | Маска и разметка вместе | Верхний слой или наложение в ffmpeg, основной файл |
| `disc-mask-2400.png` | Серое вне кольца, кольцо прозрачное | Посмотреть без разметки, как будет на диске |
| `disc-guides-2400.png` | Только разметка: круги, лучи через 30°, шкала в мм | Отдельный слой с разметкой |
| `disc-ring-luma-2400.png` | Кольцо белое, остальное чёрное | Маска слоя, `maskedmerge` |

На разметке красные круги показывают границы кольца, зелёные пунктирные границы надёжной зоны, а синие лучи и шкала помогают оценить положение.

**Шаблоны не должны попасть в итоговый файл:** их линии напечатаются. Перед экспортом скройте слой.

### GIMP, Krita, Photoshop

1. Откройте `disc-overlay-2400.png` и поместите фото слоем под ним.
2. Подвиньте и масштабируйте фото. Важное должно лечь между зелёными кругами.
3. Переведите в ч/б и настройте контраст.
4. Скройте шаблон и экспортируйте PNG 2400×2400.

### ffmpeg

Параметры подгонки:
- `S`: масштаб фото.
- `CX`, `CY`: точка фото в пикселях исходника, которая ляжет в центр диска.
- `X = 1200 - CX * S`, `Y = 1200 - CY * S`.

Пример ниже взят для `S = 1.29`, `CX = 1030`, `CY = 729`, откуда `X = -129`, `Y = 260`.

Подгонка с шаблоном поверх:
```bash
ffmpeg -y -i photo.jpg -i template/disc-overlay-2400.png -filter_complex \
  "color=white:s=2400x2400[bg];[0:v]format=gray,scale=iw*1.29:-1[fg];\
[bg][fg]overlay=x=-129:y=260:shortest=1[c];[c][1:v]overlay=format=auto" \
  -frames:v 1 -update 1 fit.png
```

Итоговый файл без шаблона, с контрастом:
```bash
ffmpeg -y -i photo.jpg -filter_complex \
  "color=white:s=2400x2400[bg];[0:v]scale=iw*1.29:-1,format=gray,eq=contrast=1.25:gamma=1.1[fg];\
[bg][fg]overlay=x=-129:y=260:shortest=1,format=gray" \
  -frames:v 1 -update 1 final.png
```

С поворотом на 30° по часовой стрелке. Поворот меняет размер кадра, поэтому `X` и `Y` подбирайте заново по `fit.png`:
```bash
ffmpeg -y -i photo.jpg -i template/disc-overlay-2400.png -filter_complex \
  "color=white:s=2400x2400[bg];[0:v]format=gray,scale=iw*1.29:-1,\
rotate=30*PI/180:ow=rotw(30*PI/180):oh=roth(30*PI/180):c=white[fg];\
[bg][fg]overlay=x=-400:y=-100:shortest=1[c];[c][1:v]overlay=format=auto" \
  -frames:v 1 -update 1 fit.png
```

### Что хорошо ложится на диск

- **Лица:** от 400 px и подальше от края.
- **Линии:** от 10–12 px, примерно 0,5 мм.
- **Текст:** высотой от 50 px, примерно 2,4 мм. Такой размер читался на тестовом диске.
- **Контраст:** крупные контрастные формы надёжнее полутонов, которые сильно зависят от угла света.
- **Отверстие:** ставьте на пустое место. В него же можно спрятать ненужный объект.

Итоговый файл можно проверить без записи:
```bash
dotnet run --project src/DiscImageStudio.Cli -c Release -- \
  cd-generate --input final.png --output track.wav --preset noname-cd-rw-infodisc --tone-dither 1
dotnet run --project src/DiscImageStudio.Cli -c Release -- \
  cd-preview-track --track track.wav --output preview.png --preset noname-cd-rw-infodisc --size 1000
```
